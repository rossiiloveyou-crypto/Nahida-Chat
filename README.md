# Nahida Chat 功能与使用手册

> 适用版本：`0.1.0`（当前仓库 `main`）
> 文档基线：2026-11-08，源码提交 `f0c8532`
> 本文描述**已落地行为**。路线图、未实现的打包/密钥加密/自动模型下载等能力会单独标注，不作为现成功能。

## 1. 项目定位

Nahida Chat 是一个**本地优先的桌面 AI 对话客户端**，基于 Electron + Vite + React + TypeScript。

它适合这些使用场景：

- 在桌面上与可配置的模型服务对话，按角色文件夹切换人格与说话风格；
- 让模型在指定的本地工作区里列出目录、读取文件、查看时间；
- 建立一个独立的“故事区”，在角色设定之上继续写剧情，并保留分支、画像与世界书；
- 把 QQ 私聊/群聊作为外部渠道接入，由白名单控制谁能触发、谁能用工具；
- 在本地保存对话、配置与长期记忆，并让记忆以可审计的方式参与下一轮对话。

它**不**是一个会自动上传数据的云端服务：桌面会话、故事、记忆、提示词与密钥都以本机文件为真源。启用远程模型或 QQ 时，相关请求自然会发往对应服务商或 QQ 客户端；这一点在“数据与隐私”一节会逐项说明。

## 2. 快速开始

### 2.1 环境要求

- Node.js `>= 20.19`（建议使用项目声明的 pnpm 版本）；
- pnpm `10.33.0`（`package.json` 的 `packageManager`）；
- Windows 桌面环境（当前主要开发/验证平台；Electron 本身跨平台，但 QQ 注入属于 Windows 场景）。

### 2.2 安装与启动

```bash
corepack enable
pnpm install
pnpm dev
```

首次启动默认使用**演示模式**：回复由本地 mock 生成，不调用远程模型。可以先用它验证“输入 → 流式显示 → 会话落盘”的完整链路。

### 2.3 接入真实模型（最短路径）

1. 打开左下角 **设置 → 模型配置**。
2. 点 **新建档案**，选择一个预设（OpenAI、DeepSeek、Kimi、通义千问、智谱、火山方舟、MiniMax、OpenRouter、Anthropic、Gemini、Ollama 或自定义 OpenAI 兼容服务）。
3. 按预设填写或确认 `baseUrl`、`apiKey`，在模型清单里添加模型 ID。
4. 点 **测试连接**；通过后点 **保存档案**。
5. 将这套档案 **设为默认**。不手动切换模型的对话和 QQ 渠道都会跟随默认档案的默认模型。

> `apiKey` 当前以明文写入 `userData/settings.json`。请不要把该文件提交到 Git、上传到工单或共享给他人。项目尚未实现 safeStorage 加密。

### 2.4 日常使用入口

左侧栏从上到下是：

- **新建对话**：创建一条普通 Chat 会话；
- **最近**：当前活动工作区下的普通会话（故事与 QQ 会话不会混入这里）；
- **故事**：故事卡片与 **+ 新建故事**；
- **设置**：模型、提示词、故事区、记忆、渠道等全局配置。

主对话区底部有三个选择器：

- **模型**：只影响当前会话，切到其他模型不会改默认档案；
- **工作区**：Agent 工具可访问的目录边界；
- **权限**：只读 / 审批 / 完全访问。

输入 `Enter` 发送，`Shift + Enter` 换行；中文输入法组词期间按 `Enter` 不会被误发送。输入超过 100,000 字只标红提醒，不硬截断。

## 3. 对话模式

### 3.1 Chat

新建对话首页的 Chat 滑块对应纯对话模式：

- 默认不会向模型提供工具；
- 仍会注入系统提示词、当前时间与已启用的长期记忆；
- 如果需要在 Chat 里使用工具，必须额外开启下文“Chat 工具增强”，并逐个勾选允许的工具。

Chat 适合日常问答、写作、角色聊天，以及不希望模型改动本地文件的场景。

### 3.2 Agent

Agent 模式面向“让模型读工作区、执行工具”的任务：

- 会向模型提供当前可用的工具定义；
- 工具是否执行由 **工作区 + 权限模式 + 渠道授权**共同决定；
- 没有任何工作区时，输入区会进入门禁态并提示先创建工作区；
- 一个会话开始有消息后不能直接切模式；要换模式请新建对话。

### 3.3 Story（故事区）

故事模式不是首页第三个滑块，而是从侧栏 **故事 → + 新建故事** 进入。每条故事区拥有：

- 自己的角色、标题、概要、背景设定；
- 自己的分支树与分支消息；
- 自己的长期记忆库；
- 可选的剧本世界书与故事画像。

故事会话不会出现在“最近”列表里，避免与普通对话混杂。

### 3.4 模式切换规则

- 空会话可以在 Chat / Agent 之间切换；
- 已有消息的会话锁定模式，新建对话才能切换；
- 故事区保持 `story` 模式，不会被塞回 Chat 滑块；
- 故事会话不向模型提供工具，工具只属于 Chat/Agent 的可配置能力。

## 4. 模型配置

### 4.1 模型档案（ModelProfile）

“模型档案”是模型配置的唯一真源，包含：

- 档案名；
- 传输适配器（演示、OpenAI 兼容、Anthropic、Gemini、Ollama）；
- 服务地址与 API Key；
- 模型清单、默认模型；
- 温度（0–2）；
- 每个模型的上下文窗口与是否多模态（用于界面提示与后续裁剪判断）。

设置页里的扁平字段（provider/baseUrl/apiKey/model）只是镜像；聊天时会重新解析档案，避免使用过期镜像。

### 4.2 可用预设

| 预设 | 传输适配器 | 说明 |
| --- | --- | --- |
| 演示模式 | mock | 完全离线，本地回显 |
| OpenAI | OpenAI 兼容 | OpenAI Chat Completions |
| DeepSeek | OpenAI 兼容 | DeepSeek API |
| 月之暗面 Kimi | OpenAI 兼容 | Moonshot API |
| 通义千问 | OpenAI 兼容 | DashScope 兼容模式 |
| 智谱 GLM | OpenAI 兼容 | 智谱开放平台 |
| 火山方舟 | OpenAI 兼容 | 火山方舟 |
| MiniMax | OpenAI 兼容 | MiniMax API |
| OpenRouter | OpenAI 兼容 | 聚合模型服务 |
| Anthropic Claude | Anthropic | Messages API |
| Google Gemini | Gemini | streamGenerateContent |
| Ollama（本地） | Ollama | 本机 11434 端口 |
| 自定义（OpenAI 兼容） | OpenAI 兼容 | 任意兼容接口 |

预设只负责预填，不锁定；地址和模型都可以改。

### 4.3 添加模型与获取清单

- 服务商实现模型清单接口时，点 **获取可用模型**，勾选后一次性加入；
- 服务商不实现或请求失败时，直接在输入框填模型 ID 后回车/点“添加”；
- 模型清单至少保留一个模型；移除当前默认模型前，请先选新的默认模型；
- “测试连接”使用当前草稿，不要求先保存档案。

### 4.4 单会话模型切换

输入框下方的模型选择器写入当前会话：

- 不会修改默认档案；
- 正在生成的那一步不受切换影响，下一次请求才使用新模型；
- 没有会话时选择会暂存为“下一句话”的模型，建立会话后带入。

### 4.5 渠道模型

QQ 私聊/群聊没有独立模型选择器，固定使用**默认档案的默认模型**。想换渠道模型，请改默认档案或其默认模型；这会同时影响没有手动切换模型的桌面对话。

## 5. 提示词与角色

### 5.1 提示词目录

提示词是用户资产，程序不写死任何角色人格。目录结构如下：

```text
Prompt/
├─ shared/
│  ├─ base.md                 全局底线规则（所有角色、所有模式）
│  ├─ tone.md                 语气与句式（所有角色、所有模式）
│  └─ tool_usage.md           工具规范（仅 Agent）
└─ characters/
   └─ <角色 id>/
      ├─ soul.md              人格核心
      ├─ canon/*.md           原作台词样本（可选）
      ├─ worldbook/*.md       背景设定
      ├─ modes/{chat,agent,story}.md   各模式规则
      └─ styles/{chat,agent,story}.md  各模式表达风格
```

实际拼装顺序是：

1. `shared/base.md`
2. `shared/tone.md`
3. `characters/<id>/soul.md`
4. `characters/<id>/canon/*.md`
5. `characters/<id>/worldbook/*.md`（故事“完全覆盖”档位时跳过）
6. 剧本世界书 `worldbookDir/*.md`（故事区可选）
7. 故事背景与剧本设定（故事区可选）
8. `characters/<id>/modes/<mode>.md`
9. `characters/<id>/styles/<mode>.md`
10. 故事用户画像 `profile.md`（故事区可选）
11. `shared/tool_usage.md`（仅当本轮真有工具）

缺哪个文件就跳过哪个，不报错。

### 5.2 在设置页做什么

**设置 → 系统提示词**只做三件事：

- 展示注入顺序与“改哪个文件”；
- 打开整个提示词目录或某个角色目录；
- 将某个角色设为新对话默认。

设置页**不显示也不编辑提示词正文**，正文请用外部编辑器直接改 `Prompt/` 下的文件。这样只有一份真源。

### 5.3 新增角色

1. 在 `Prompt/characters/` 下新建一个文件夹，文件夹名就是角色 id；
2. 至少写 `soul.md`，否则设置页会标为缺少人格核心；
3. 按需添加 `worldbook/`、`canon/`、`modes/`、`styles/`；
4. 回到 **设置 → 系统提示词**，刷新或重新进入页面即可看到新角色；
5. 可在该页设为“新对话默认”，或新建故事时选择该角色。

不需要改代码。

### 5.4 世界书（Worldbook）

世界书是背景设定条目库。一个世界书是一个目录，目录里每个 `.md` 文件可包含多个条目；`README.md` 是索引，不会被当成条目文件。

每个条目的格式：

```markdown
## 条目名
- id: <32 位十六进制>
- 触发词: 钟楼, 报时, 停摆
- 常驻: 否
- 优先级: 5
- 内在价值: 50
- 连带触发词: 无

正文……
---
```

字段含义：

- **触发词**：命中后激活该条目；逗号、顿号都可分隔；
- **常驻**：为“是”时始终注入，不参与普通触发；
- **优先级**：1–10，激活后的排序 tiebreak；
- **内在价值**：0–100，抗遗忘基准；
- **连带触发词**：本条命中时顺带激活其它条目，一层封顶。

**设置 → 系统提示词 → 打开世界书编辑器**支持：

- 选择已知角色世界书或故事剧本世界书；
- 选择任意目录/任意 `.md` 文件；
- 新建世界书；
- 按标题或触发词搜索条目（大小写无关）；
- 新增、编辑、删除条目；
- 缺 `id` 的合规条目会保留并标记，保存时自动补 id；
- 同文件内触发词重复只提醒，不阻止保存；
- 写入目录有路径守卫，写入前保留 `.bak` 并原子替换。

编辑器默认先显示 8 条，其余通过“展开”查看；搜索会过滤当前列表，但不会修改磁盘上的条目顺序。

### 5.5 故事区专用设定

- **背景与剧本设定**：描述环境与场景，属于设定层，不是第一条消息；
- **用户画像 `profile.md`**：描述“你”在这个故事里是谁，只对本故事生效；
- **剧本世界书目录**：可指定一个独立目录；
- **世界书档位**：
  - **两段都注入**：角色 worldbook + 剧本世界书；
  - **完全覆盖**：只注入剧本世界书，跳过角色 worldbook。

“完全覆盖”必须提供剧本世界书目录，否则该故事的世界书会整段消失。

## 6. 故事区

### 6.1 新建故事

从侧栏 **故事 → + 新建故事** 打开表单，填写：

- 标题（必填）；
- 角色；
- 剧本世界书目录（可空）；
- 世界书档位；
- 背景与剧本设定（可空）；
- 开场消息（可空，非空时会写成该故事根分支的首条 assistant 消息）。

创建后会进入该故事的当前活跃分支。

### 6.2 分支

右侧 **分支** 抽屉是故事区的结构视图：

- **检索**：在当前故事的全部分支里检索，点击命中可跳到对应分支和消息；
- **分支树**：显示父子分支、消息数、最近活动时间；点击可切换；
- **消息时间轴**：列出当前分支消息，可从任意一条消息之后“由此分支”；
- 派生新分支会激活新分支；原分支不受影响；
- 不能删除当前活跃分支；
- 不能删除仍有子分支的分支；先处理子分支；
- 删除分支不可恢复，确认框会提示消息数量。

分支复制的是分叉点之前的消息前缀；旁白也会作为消息一起复制。

### 6.3 检索

抽屉检索范围是**整条故事的所有分支**，不是只看当前分支。结果会显示：

- 所属分支；
- 消息序号；
- 角色（我 / 她 / 旁白）；
- 截断后的命中片段。

点击结果会自动切换到对应分支，并滚动、短暂高亮该消息。

### 6.4 旁白

故事输入框左侧有 **对话 / 旁白** 徽章。

使用“旁白”时：

- 输入内容**不调用 LLM**；
- 不创建用户消息，也不显示用户头像气泡；
- 消息区以居中文字显示“旁白：xxxxx”；
- 旁白会立即写入会话并持久化；
- 下一次发送普通“对话”时，旁白会作为独立的 **system** 消息、带“系统旁白：”前缀进入模型上下文；
- 正在生成时不能插入旁白，避免打乱本轮顺序。

普通 Chat/Agent 会话不显示这个徽章。

### 6.5 故事设置与删除

**设置 → 故事区**可以：

- 查看全部故事区；
- 修改标题、概要、角色、背景与世界书档位；
- 编辑用户画像；
- 查看/删除/清空该故事自己的长期记忆；
- 删除整个故事区。

删除故事区会连同该区记忆库与所有分支一起删除，**不可恢复**。程序会在删除前自动备份到 `stories/.trash/`，但不要把备份当成常规版本管理。

### 6.6 故事数据路径

每个故事区是自包含目录：

```text
userData/stories/<storyId>/
├─ story.json        元信息
├─ branches.json     分支元数据（首次读取时可能懒迁移生成）
├─ profile.md        用户画像（可不存在）
└─ memory.db         该故事自己的长期记忆库
```

删除前的备份位于 `userData/stories/.trash/`，不在被删目录内部。

## 7. 工作区与工具权限

### 7.1 工作区

工作区是一个本地目录，决定 Agent（以及开启工具增强的 Chat）能读写的根。支持多个工作区：

- 侧栏在 Agent 模式下显示工作区列表；
- 输入框下方也能切换当前会话工作区；
- 新建对话、设置当前活动工作区、删除工作区都会影响后续会话的默认落点；
- 删除工作区前请确认没有会话依赖它；删除后会话会被重新指派到其他活动工作区。

零工作区时，Agent 输入区会门禁，点击输入区可按引导创建目录。

### 7.2 三种权限模式

| 模式 | 只读工具 | 有副作用工具 | 路径 |
| --- | --- | --- | --- |
| 只读 | 直接执行 | 一律拒绝 | 限工作区内 |
| 审批（默认） | 直接执行 | 弹确认卡，超时按拒绝 | 限工作区内 |
| 完全访问 | 直接执行 | 直接执行 | 不受工作区限制 |

“只读/有副作用”由工具定义里的 `readOnly` 字段决定。切换权限后，下一轮工具调用立即按新配置执行。

### 7.3 当前内置工具

- `fs.list_dir`：列出工作区目录，最多显示 200 项；
- `fs.read_file`：读取文本文件，最多 64 KB，遇到二进制内容拒绝；
- `clock.now`：获取本机或指定 IANA 时区的当前时间。

工具错误不会炸掉整轮对话，而会作为工具结果回喂模型。

### 7.4 Chat 工具增强

Chat 默认拿不到任何工具。若需要：

1. **设置 → 工具权限 → Chat 工具增强**，打开总开关；
2. 在逐工具列表中勾选允许的工具；
3. 保留/调整全局权限模式；
4. 回到 Chat 会话发送消息。

总开关关闭时，Chat 拿不到工具；已勾选条目会保留。这里控制的是“是否供给”，最终执行还受权限模式与渠道授权约束。

## 8. 长期记忆（RAG）

### 8.1 能力概述

长期记忆是跨会话的事实库，不是把整段聊天全文入库。它主要记录用户说过的稳定事实，并通过检索在下一轮作为独立 system 段注入。

- 混合检索：向量相似度 + SQLite FTS5 关键词；
- 全链路本地 embedding，不把对话内容发去外部做 embedding；
- 模型缺失时降级为关键词检索，其余对话照常；
- 每轮开始时只检索一次，控制开销；
- 超预算整条丢弃，不切半句。

### 8.2 使用方式

**设置 → 长期记忆**可以：

- 开关总开关；
- 开关自动提炼；
- 调整召回条数 `topK`、token 预算、分数下限；
- 用一段话“试召回”，查看综合分/向量分/关键词分；
- 手动添加一条事实；
- 查看、删除、清空记忆；
- 打开模型目录，按路径放置 embedding 模型。

### 8.3 放置 embedding 模型

模型不随仓库分发。默认目录：

```text
models/Xenova/bge-m3/
├─ config.json
├─ tokenizer.json
├─ tokenizer_config.json
├─ special_tokens_map.json
├─ sentencepiece.bpe.model
└─ onnx/model_quantized.onnx
```

缺少模型时不会报错阻断对话，只会降级。具体下载来源、实测数据与设计细节见 [docs/04-RAG记忆检索设计.md](docs/04-RAG记忆检索设计.md)。

### 8.4 记忆域与故事记忆

- 桌面对话写入主记忆域；
- 故事区使用自己目录里的 `memory.db`，物理隔离；
- 故事分支记忆记录来源消息下标；检索时按当前分支到祖先分支的消息前缀长度过滤，只让在该分叉点之前产生的记忆可见；
- “区块”可以为不同渠道会话划分共享记忆域；
- 某个故事区的记忆可在 **设置 → 故事区** 单独查看与清理。

### 8.5 隐私边界

记忆检索与 embedding 在本机执行，但“记忆注入”会把命中事实交给当前模型。若使用远程模型，这部分内容会随请求发给服务商。不要把不愿发送的敏感事实放进记忆，或使用本地 Ollama。

## 9. 区块与渠道（QQ）

### 9.1 区块（过渡能力）

区块（Zone）是当前代码里用于划分**记忆域**的过渡机制。它不会把多个群合并成一条会话；每个群仍然是独立会话。

> ⚠️ 区块将在下一阶段任务中废弃。现阶段可以查看它，但**不建议**围绕区块建立长期配置或工作流。新设计落地后，相关设置与数据结构可能被移除。

当前版本仍保留：

- `root` 主区块与自定义区块；
- 将渠道白名单中的会话加入某个区块；
- 区块级画像/旁听开关字段。

其中画像注入与旁听开关尚未接入聊天/采集主路径；不要把它们当作稳定功能。

### 9.2 渠道控制台

**设置 → 渠道控制台**按“人”授权，核心数据是真源 `userData/channels/access.json`：

- **QQ 号白名单**：一行一个号，分别控制私聊、群聊、工具三个权限位；
- **群白名单**：决定某个群是否允许她说话；
- **鉴权开关**：
  - 群成员鉴权（默认关）：开启后，账号表中的“群聊”位才生效；
  - 工具调用拦截（默认开）：不允许的人不能执行工具；
  - 群聊工具增强（默认开）：群聊里的工具供给；
- **渠道工作区**：QQ 会话唯一允许落地的文件根，默认 `userData/workspace`；
- **渠道模型**：跟随默认档案的默认模型；
- **旁听库**：只增不清的群语料，只读，不参与记忆注入；采集资格由 QQ 桥规则决定，区块里的旁听开关当前不改变采集行为。

只有两层都满足，群里才有工具可用：**群聊工具增强开关打开 + 账号的“工具”位勾选**；最终还要看全局工具权限模式。

### 9.3 QQ 接入步骤

1. 先启动并登录 QQ；
2. 打开 **设置 → QQ 接入**，点“刷新”查看本机 QQ 主进程；
3. 在目标 PID 行点 **注入**。程序不会自动挑进程；
4. 状态变为“在线/已注入”后，去 **设置 → 渠道控制台** 配置账号/群白名单；
5. 在群里通常需要 @ 她（可在 QQ 接入 → 行为开关里调整）；
6. 观察 **最近事件** 确认回复/丢弃原因。

如果宿主降级，QQ 接入页会提示；先确认 `out/snowluma-host` 下的 `node.exe` 与 `index.mjs` 存在，再点“重启宿主”。

### 9.4 QQ 行为开关

在 **设置 → QQ 接入 → 行为开关** 可以调整：

- typing 提示方式与文本（仅私聊）；
- 群里是否必须 @；
- 群聊首段是否 @ 提问者；
- 分段延迟、最大段数、单段码点上限；
- 每用户/每渠道 60 秒限速；
- 出错时是否回复一句提示。

这些设置控制出站观感与限流，不代替渠道授权。

## 10. 数据、备份与隐私

### 10.1 主要数据位置

路径中的 `userData` 可在 **设置 → 关于 → 数据目录** 查看。典型文件/目录：

| 路径 | 内容 |
| --- | --- |
| `settings.json` | 模型档案、工具权限、记忆参数、工作区、外观 |
| `sessions.json` | 普通会话、故事分支会话、旁白与消息历史 |
| `memory.db` | 主长期记忆库 |
| `zones.json` | 区块与记忆域配置（过渡能力，下一阶段废弃） |
| `stories/<storyId>/` | 故事元信息、分支、画像、独立记忆库 |
| `stories/.trash/` | 删除故事区前的自动备份 |
| `channels/access.json` | 渠道按人授权与群白名单 |
| `workspace/` | 默认工作区 / 渠道工作区 |
| `snowluma/` | QQ 宿主运行时数据 |
| `models/` | 本地 embedding 模型（不随仓库分发） |

提示词不在 userData 内，而在应用根的 `Prompt/`（开发模式是仓库目录，打包后可能是 `resources/prompt`）。

### 10.2 建议备份

最小备份集合：

- `settings.json`
- `sessions.json`
- `memory.db`
- `zones.json`
- `stories/`
- `channels/access.json`
- `Prompt/`

备份前先退出应用，避免 SQLite 的 `-wal` / `-shm` 文件没有被正确回收。

### 10.3 隐私与安全边界

- 桌面会话历史、故事、记忆库、世界书与提示词均在本机；
- `apiKey` 当前明文存在 `settings.json`，**尚未加密**；
- 使用远程模型时，提示词、上下文、工具结果与记忆命中会随请求发送给模型服务商；
- QQ 接入会把相关消息交给 QQ 客户端/宿主，并按配置回复；
- 工具的“完全访问”模式不受工作区限制，请只在信任模型与当前任务时使用；
- 审批模式下有副作用工具会等待确认，超时按拒绝处理；QQ 没有审批卡，因此审批模式下的副作用工具在 QQ 中等于拒绝；
- 不要把 `settings.json`、`sessions.json`、`memory.db` 或含密钥的日志提交到公开仓库。

## 12. 已知边界与未完成项

以下内容在当前版本中**不存在**或仍有明确限制：

- 没有正式安装包/自动更新（打包配置尚未落地）；
- `apiKey` 没有使用 Electron safeStorage 加密；
- embedding 模型不会自动下载，需要手动放置；
- 没有多窗口与多主题皮肤；主题仅浅色/深色/跟随系统；`Ctrl/Cmd + Shift + G` 只用于开发态 UI 网格，不是业务快捷键；
- 工具集当前只有只读的目录列表、读文件与时钟；没有通用写文件/命令执行工具；
- QQ 注入依赖本机 QQ 与 Windows 宿主环境，不保证所有 QQ 版本可用；
- 故事区与普通会话的侧栏是分开的，故事不会出现在“最近”；
- 区块是过渡能力，将在下一阶段废弃；不建议继续为其做长期配置；
- 旧数据迁移路径存在，但升级前仍建议备份 `userData` 与 `Prompt/`。
