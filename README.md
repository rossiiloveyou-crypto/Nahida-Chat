# Nahida Chat 功能与使用手册

> 适用版本：**`1.1.1`**（含 2026-11-24 待发布变更）
> 文档基线：**2026-11-24**（基于当前代码实际实现编写，未实现的能力在文末单独说明）

## 1. 项目定位

Nahida Chat 是一个**本地优先的桌面 AI 对话客户端**，基于 Electron + Vite + React + TypeScript。

它适合这些使用场景：

- 在桌面上与可配置的模型服务对话，按角色文件夹切换人格与说话风格；
- 让模型在指定的本地工作区里列出目录、读取文件、查看时间；
- 建立独立的「故事区」，在角色设定之上推进剧情，支持分支、用户画像、世界书与历史轮次召回；
- 将故事区的生成环节桥接到本机 SillyTavern（ST），由 ST 角色卡与预设出字、Nahida Chat 管理上下文预算与分支；
- 在 SillyTavern（JSONL）与 Nahida Chat 备份（`.nc.json`）之间预览、导入与导出桌面对话；
- 把 QQ 私聊与群聊作为外部渠道接入，按账号与群白名单控制回复、工具与指令权限；
- 在本地保存对话、配置、摘要与长期记忆，并以可审计的方式参与后续对话；
- 需要彻底重来时，可一键清空所有人的会话、记忆、人设历史、摘要与故事区（保留设置与授权，清空后自动重启）。

Nahida Chat **不**是一个会自动上传数据的云端服务：桌面会话、故事、记忆、提示词与密钥都以本机文件为真源。启用远程模型或 QQ 接入时，相关请求会发往对应模型服务商或本机 QQ 客户端，具体边界见「数据、对话迁移与隐私」一节。

## 2. 快速开始

### 2.1 环境要求

- Node.js `^24.22.1 || >=26.12.1`
- pnpm `11.25.0`（可通过 `corepack` 自动切换）
- Windows 桌面环境（当前主要开发与打包验证平台；Electron 本身跨平台，但 QQ 注入依赖 Windows 宿主环境）

### 2.2 安装与启动

```bash
corepack enable
pnpm install
node .\node_modules\electron\install.js
pnpm dev
```

首次启动默认使用**演示模式**：回复由本地离线 mock 生成，不调用远程模型，可用于验证「输入 → 流式显示 → 会话落盘」的完整链路。

### 2.3 接入真实模型（最短路径）

1. 打开左下角 **设置 → 模型配置**。
2. 点击 **新建档案**，选择一个服务商预设（OpenAI、DeepSeek、月之暗面 Kimi、通义千问、智谱 GLM、火山方舟、MiniMax、OpenRouter、Anthropic Claude、Google Gemini、Ollama 或自定义 OpenAI 兼容服务）。
3. 填写或确认 `baseUrl`、`apiKey`，并在模型清单中添加模型 ID。
4. 点击 **测试连接**；通过后点击 **保存档案**。
5. 将该档案 **设为默认**。未手动指定模型的桌面对话和 QQ 渠道都会跟随默认档案的默认模型。

> `apiKey` 当前以明文保存在 `userData/settings.json` 中，尚未接入 Electron `safeStorage` 加密。请勿将该文件提交到 Git 或分享给他人。

### 2.4 日常使用入口

左侧栏从上到下依次为：

- **新建对话**：回到首页创建普通会话；
- **工作区**（仅在 Agent 模式下显示）：管理当前可访问的本地目录；
- **最近**：当前活动工作区下的普通会话（故事与 QQ 渠道会话不会混入这里）；
- **故事**：已有故事卡片列表，**只用于快速打开**；新建故事的入口位于主页面首页的模式滑块中（见 3.3 与 6.1）；
- **底部入口**：提供 **导入对话**（从酒馆 JSONL 或 NC 备份导入会话）与 **设置**。设置页分为「基础设置」（模型配置、系统提示词、故事区）、「能力与安全」（长期记忆、渠道控制台、QQ 接入、工具权限）、「其他」（ST 桥接、数据与备份、外观、关于）。

对话页右上角提供 **「⋯」** 按钮用于导出当前会话或全部桌面会话；输入区底部有四个选择器（从左到右）：

- **角色**：决定当前对话由谁扮演，切换后下一轮即生效（见 5.3）；
- **模型**：只影响当前会话，不会修改默认档案；
- **工作区**：Agent 工具（及开启工具增强的 Chat）可访问的目录边界；
- **权限**：只读 / 审批 / 完全访问。

按 `Enter` 发送，`Shift + Enter` 换行；中文输入法组词期间按 `Enter` 不会误发送。输入超过 100,000 字时仅标红提醒，不硬截断。

## 3. 对话模式与交互

### 3.1 Chat

首页模式滑块选 **Chat** 进入纯对话模式：

- 默认不向模型提供任何工具；
- 仍会注入系统提示词、当前时间、已启用的长期记忆与对话摘要；
- 如需在 Chat 中使用工具，可在 **设置 → 工具权限 → Chat 工具增强** 开启总开关并逐个勾选允许的工具。

### 3.2 Agent

首页模式滑块选 **Agent** 进入任务执行模式：

- 向模型提供当前已注册的工具定义；
- 工具能否执行由 **工作区 + 权限模式 + 渠道授权** 共同决定；
- 当本机尚未添加任何工作区时，输入区会进入门禁引导态，点击输入区即可选择目录创建工作区。

### 3.3 Story（故事区）

首页模式滑块有 **Chat / Agent / 故事** 三项。切换到 **故事** 后，首页会隐藏普通输入框，展示 **「+ 新建故事」** 按钮与最近故事列表；左侧栏的「故事」区同样提供已有故事卡片的快速打开入口。

每个故事区独立拥有：

- 自己的角色、标题、概要、背景与剧本设定；
- 自己的用户画像（`profile.md`）与可选的剧本世界书；
- 自己的分支列表与分支消息（分支之间互相独立）；
- 自己独立的长期记忆库与历史轮次归档（`memory.db`）。

故事会话不会出现在左侧栏「最近」列表中，且不向模型提供工具。

### 3.4 模式切换规则

- 新建的空会话（尚未产生消息）可以通过首页模式滑块在 **Chat / Agent / 故事** 之间切换；切换到 **故事** 会进入故事创建与打开界面，不会把已有空会话改写成无故事归属的会话；
- 已有消息的会话会锁定模式，需点击 **新建对话** 才能换用其他模式；
- 已进入的故事区即使还没有消息，也保持 `story` 模式，不会再显示首页三段式模式滑块；
- **角色切换不受此限制**：普通对话可随时在输入框下方切换角色，历史消息保持不变，下一轮生效（故事区的角色归故事本身管理，需在 **设置 → 故事区** 修改）。

### 3.5 对话预发送

在非渠道会话（桌面 Chat / Agent / 故事）中，输入区上方提供 **「预发送：关 / 开」** 开关（按会话记忆）：

- 开启后，按 `Enter` 或点击发送按钮只会把内容追加到会话记录中，**不会立即触发模型生成**；
- 同时会出现独立的 **「请求回复」** 按钮，点击后才触发一次回复（仅回复已发送进会话的内容，不会把输入框中尚未发送的草稿发出去）；
- 在故事区仅追加了旁白而未发用户对话时，也可以点击「请求回复」让角色接续；
- QQ 渠道会话不提供预发送模式。

### 3.6 思考过程（推理模型）

接入支持推理过程的模型时，回复气泡上方会自动出现折叠块，展示模型的思考内容：

- **思考中**：折叠块自动展开、流式追加，期间可点击停止按钮中断；
- **开始输出正文**：折叠块自动收起，仅显示「已思考 · N 字」，点击可随时展开回看；
- **手动操作优先**：手动展开或收起后，不再自动收起。

已适配的服务商与协议字段：

| 服务商 | 协议字段 | 说明 |
| --- | --- | --- |
| DeepSeek / 通义千问 / 智谱 GLM / Kimi（OpenAI 兼容） | `delta.reasoning_content` | 常见推理字段 |
| OpenRouter 及部分中转 | `delta.reasoning` | 自动识别 |
| 部分自建网关 | `delta.thinking` | 兜底识别 |
| Anthropic | `thinking_delta` | 需服务端开启 extended thinking |
| Gemini | `parts[].thought === true` | 与正文共用 text 字段，通过 thought 标记区分 |
| Ollama | `message.thinking` | 0.6+ 推理模型 |

边界说明：

1. 思考过程**仅用于展示，绝不回灌**到下一轮请求上下文；
2. 思考过程**不混入回复正文**，也不会经由 QQ 发送给对端；
3. 演示模式（离线 mock）也会生成一段明确标注为演示用途的思考文本，便于首次安装时预览交互形态。

### 3.7 出错、中断与重试

当某轮请求失败（密钥失效、网络异常、服务端 5xx、生成中途断流）时，对应助手气泡会进入失败态：

- 气泡内直接展示错误原因，并随消息一起落盘，重启应用后仍可见；
- 气泡下方提供 **重试这一轮**（仅最后一条助手消息）和 **删除这条**；
- **重试**会复用原消息 ID，清空其正文、思考过程与工具记录后重新生成，不重复新增用户消息；
- 点击停止且正文为空时，或应用异常退出留下未完成的 `streaming` 消息时，均会收敛为可重试的失败态（已生成的半截正文会保留）。

### 3.8 消息编辑、重发与删除

每条消息下方按可用性提供操作图标：

| 动作 | 适用范围 | 行为 |
| --- | --- | --- |
| **编辑** | 用户消息与旁白 | 原地修改正文，提供 **保存不发送** 与 **保存并重新提问**（丢弃其后全部消息并重跑一轮，需二次确认） |
| **重试** | 最后一条助手回复 | 重跑本轮，不新增用户消息 |
| **删除** | 所有消息 | 仅删除该条消息，其余对话保留，删除后不再进入上下文 |
| **复制** | 有正文的消息 | 复制落库原稿（而非显示层加工后的 HTML） |

边界规则：

- QQ 渠道会话为只读展示，不渲染编辑、重试、删除按钮；
- 模型生成期间禁用编辑与删除；
- 进入消息编辑态时锁定底部输入框发送，避免保存与新发送冲突；
- 不允许将消息编辑为空串，移除消息请使用 **删除**。

### 3.9 显示管线：Markdown、标签卡片与剧情/对话分色

消息气泡的显示层独立于落库原文（数据库和 `sessions.json` 始终保存原稿），按以下顺序处理展示：

1. **ST 正则（Markdown 显示通道）**：读取已配置的 `regex_scripts`，仅运行标记为 `markdownOnly` 且作用于 `AI_OUTPUT` 的脚本；`promptOnly` 脚本由 ST 组装请求时处理，显示层不重复执行。
2. **结构化标签卡片**：如果某条预设脚本试图把 `<wave_plan>`、`<wave_summary>` 等自定义结构化标签替换成包含 `<iframe>`、`<script>`、`<style>` 等 HTML 宿主内容，安全引擎会拦截该替换，改由客户端原生折叠卡展示标签内的纯文本（默认收起）。
3. **Markdown 渲染与净化**：正常渲染标题、粗体、列表、代码块等，产物经过 DOMPurify 白名单净化。
4. **剧情 / 对话分色**：
   - 引号内对白（支持 `""`、`“”`、`«»`、`「」`、`『』`、`＂＂` 六种引号）自动包裹为 `<q>` 并高亮为橙色，仅作用于普通文本节点，不影响代码块、行内代码与链接属性；
   - `*动作*` 渲染为偏灰斜体；
   - 故事旁白保持正文色。浅色与深色主题各有一套配色取值。

## 4. 模型配置与 ST 桥接

### 4.1 模型档案（ModelProfile）

「模型档案」是模型配置的唯一真源，包含档案名、传输适配器（演示、OpenAI 兼容、Anthropic、Gemini、Ollama）、服务地址、API Key、模型清单、默认模型、温度（0–2）以及每个模型的上下文窗口与多模态标记。

### 4.2 内置预设

| 预设 | 传输适配器 | 说明 |
| --- | --- | --- |
| 演示模式（离线） | mock | 完全离线，本地回显 |
| OpenAI | OpenAI 兼容 | OpenAI Chat Completions |
| DeepSeek | OpenAI 兼容 | DeepSeek API |
| 月之暗面 Kimi | OpenAI 兼容 | Moonshot API |
| 通义千问 | OpenAI 兼容 | DashScope 兼容模式 |
| 智谱 GLM | OpenAI 兼容 | 智谱开放平台 |
| 火山方舟 | OpenAI 兼容 | 火山方舟 |
| MiniMax | OpenAI 兼容 | MiniMax API |
| OpenRouter | OpenAI 兼容 | 聚合模型服务 |
| Anthropic Claude | Anthropic | Messages API |
| Google Gemini | Gemini | streamGenerateContent |
| Ollama（本地） | Ollama | 本机 11434 端口 |
| 自定义（OpenAI 兼容） | OpenAI 兼容 | 任意兼容接口 |

预设仅用于预填，不锁定地址或模型清单。

### 4.3 模型清单与切换规则

- 支持通过 **获取可用模型** 拉取服务商模型列表并批量勾选，也支持手动输入模型 ID 添加；
- 每个档案至少保留一个模型；删除当前默认模型前需先指定新默认模型；
- **测试连接**直接针对当前表单草稿测试，无需先保存；
- 对话页底部的模型选择器仅写入当前会话，不改动默认档案；正在生成的本轮不受影响，下一轮起生效；
- QQ 渠道没有独立模型选择器，固定跟随**默认档案的默认模型**。

### 4.4 ST 桥接（故事模式由 SillyTavern 生成）

故事区可将生成环节交给本机 SillyTavern（ST）执行：**角色卡、世界书与预设由 ST 负责；时间、长期记忆、故事召回、摘要、故事背景、用户画像与对话历史由 Nahida Chat 注入**。Chat、Agent 与 QQ 渠道会话不受影响。

**生效条件**（三者同时满足）：

```text
会话是 story 模式  ∧  不是渠道会话  ∧  设置中开启「故事模式走 ST 桥接」
```

任一条件不满足时自动走普通模型档案路径。桥接生效期间，对话页底部的模型选择器会置灰锁定（生成模型在 ST 内设置）。

**配置与启动**（**设置 → ST 桥接**）：

- **ST 目录**：包含 `server.js` 的本机 ST 安装目录；
- **桥接角色**：打开 ST 前必须填写 ST 中已导入的角色卡名称（需在 ST 内手动导入角色卡并配置好模型与世界书，Nahida Chat 不自动导入卡或世界书）。点击「打开 ST」时自动选中该角色；若在 ST 窗口内手动切换到其他角色卡或群组，该轮生成会报错并提示切回；
- **端口**：默认 `8000`（范围 `1–65535`）；
- **Node 路径（可选）**：留空时依次探测 `PATH` 中的 `node` 与 Electron 内置 Node 模式；
- **单轮上限（秒）**：单轮生成超时阈值，默认 `180` 秒（范围 `10–3600` 秒），超时即中止生成并判定失败；
- **运行期锁定与进程控制**：ST 运行期间，目录、桥接角色、端口、Node 路径与单轮上限均不可修改，需先点击「停止 ST」。主进程托管 ST 子进程与可见窗口，数据落在 `<ST目录>/data-nc/`，日志位于 `<ST目录>/data-nc/logs/st-bridge.log`（按 32 MB 轮转）。关闭总开关只切换生成路由，停进程请点击「停止 ST」。

**最高权重规则**：

- 在 **设置 → ST 桥接 → 最高权重规则** 中可填写补充规则（默认留空，保存于 `userData/nc-bridge/st-override.md`，超过 8,000 字符会截断并提示）；
- 仅在故事模式 ST 桥接时生效，每轮生成前追加注入，期望在与角色卡或预设冲突时优先采用（模型未必完全遵循）；清空并保存即停用。

**上下文预算分层**：

- 桥接默认开启上下文预算管理：每轮读取 ST 实时上下文长度并减去回复预留作为总预算（无法读取实时值时可使用手填预算回落），默认保留 **35%** 给 ST 侧的世界书与预设；
- 超出预算时**只省略最老的连续历史消息**，始终保留最新一条用户消息（确保模型看到的是完整的近期连续上下文）；若仍不足，才依次压缩故事召回与事实记忆预算；固定提示词、人格与对话摘要保持原文不裁剪；
- 当连最小必要集（固定上下文与最新用户消息尾缀）都放不下时，会在**发送前**直接报错中止，不把残缺上下文发给模型；
- 发生历史省略时，界面会明确提示本轮省略了多少条更早的消息；若在桥接配置文件中将 `budgetEnabled` 设为 `false`，即回到不分层裁剪的旧路径。

**健壮性、熔断与运行状态**：

- **自动恢复与熔断**：ST 页面崩溃或连接中断后，每轮最多自动恢复一次；连续两次自动恢复失败即触发 **60 秒熔断**并暂停自动重试（60 秒后自动解除，也可手动点击「打开 ST」恢复）；
- **可读的失败提示**：17 类失败步骤（启动前检查、端口占用、Node 不可用、就绪超时、接口不兼容、角色未填/缺失/重名/被切换、上下文准备失败、上下文预算不足、生成超时、空回复、落盘校验失败、落盘超时、临时会话清理失败、页面崩溃）均对应明确的中文提示，详细技术日志保留在日志文件中；
- **运行状态面板**（只读）：集中展示预算分层状态（开关、预算来源、总预算、已用、ST 侧预留、省略历史条数）、已检测角色卡、ST 进程与 PID、端口与窗口状态、日志大小与路径、Node 来源、孤儿进程数、重建次数、连续自动恢复失败次数、熔断与孤儿清单扫描错误提示、最近失败步骤与最近错误，以及联动展示的**故事召回状态**（已归档轮数、向量可用性及前往「长期记忆」的快捷入口）。

**单轮落盘闭环与运行特征**：

- 每轮生成前清理 ST 页面内存状态，并临时压制 `auto_continue` 与 `auto_swipe`（轮末必定还原，不改写 ST 配置文件）；
- 每轮使用一次性临时 chat 文件承接 ST 存盘，等待文件稳定并校验行数与末条非空助手消息后取出正文；收尾时还原原会话名、清理内存状态并删除临时文件（若删除失败则记入孤儿清单供后续清理），ST 原生 `backups/` 目录有意保留；
- **两项运行特征**：① 每轮收尾包含约 10.5 秒的备份节流观察窗口；② 故事正文在生成完成且落盘校验通过后一次性呈现，不逐字流式输出。

## 5. 提示词与角色

### 5.1 两层提示词目录

提示词按两层读取：只读内置层（开发时为 `<repo>/Prompt`，打包后为 `<resources>/prompt`）与可写自定义层（`<userData>/prompt`）。内置角色（纳西妲、妲妮娅、ST）随版本更新，自定义角色存放在用户目录，升级安装包不会丢失。两层结构一致：

```text
Prompt/
├─ shared/
│  ├─ base.md                 全局底线规则（所有角色、所有模式）
│  ├─ tone.md                 语气与句式（所有角色、所有模式）
│  └─ tool_usage.md           工具规范（仅当本轮有工具时注入）
└─ characters/
   └─ <角色 id>/
      ├─ description.md       一句话角色描述（可选，仅设置页展示，不进提示词）
      ├─ soul.md              人格核心
      ├─ canon/*.md           原作台词样本（可选）
      ├─ worldbook/*.md       背景设定
      ├─ modes/{chat,agent,story}.md   各模式规则
      └─ styles/{chat,agent,story}.md  各模式表达风格
```

实际拼装顺序：

1. `shared/base.md`
2. `shared/tone.md`
3. `characters/<id>/soul.md`
4. `characters/<id>/canon/*.md`
5. `characters/<id>/worldbook/*.md`（故事设为「完全覆盖」档位时跳过）
6. 剧本世界书 `worldbookDir/*.md`（故事区可选）
7. 故事背景与剧本设定（故事区可选）
8. `characters/<id>/modes/<mode>.md`
9. `characters/<id>/styles/<mode>.md`
10. 故事用户画像 `profile.md`（故事区可选）
11. `shared/tool_usage.md`（仅当本轮实际提供工具时注入）

缺失的文件自动跳过，不报错。角色根目录的 `description.md` 仅取首个正文段落（超过 200 字截断）用于设置页角色卡展示，**绝不参与拼装、不进入模型提示词**。

### 5.2 管理与新增角色

**设置 → 系统提示词**用于查看注入顺序、查看角色来源（内置 / 自定义）与一句话描述、打开提示词或角色目录，以及设置「新对话默认角色」。角色卡内的文件清单默认收起，标题行保留「文件 N 个」与红色缺失计数，点击可展开逐项检查。正文修改请直接使用外部编辑器编辑 `<userData>/prompt/` 下的文件。

新增自定义角色：

1. 点击 **添加自定义角色** 打开 `<userData>/prompt/characters/`，新建以角色 ID 命名的文件夹；
2. 至少编写 `soul.md`（缺此文件会被标记为不完整，在对话页角色菜单中置灰）；
3. 按需添加 `description.md`、`worldbook/`、`canon/`、`modes/`、`styles/`；
4. 刷新提示词页即可在设置页与对话页角色选择器中看到该角色。

同名用户角色会**整体遮蔽**内置角色，不会把内置层缺失文件混入；`shared/` 下的全局文件则按单文件覆盖。

### 5.3 对话页切换角色

对话页输入区最左侧的选择器列出提示词库中的全部角色：

| 操作 | 结果 |
| --- | --- |
| 普通对话中切换 | 更新当前会话的 `characterId`，同时更新「新对话默认角色」；历史消息不变，下一轮生效 |
| 故事会话 | 选择器置灰锁定；故事角色归故事区本身，需在 **设置 → 故事区** 修改 |
| 缺少 `soul.md` 的角色 | 列出但置灰，无法选中 |

主进程会校验角色目录真实存在，防止拼写错误导致静默丢失人格。切换 AI 角色不会切换长期记忆库（记忆按「用户 × 用户人设」分区，见 8.4）。

### 5.4 世界书（Worldbook）

世界书是一个包含若干 `.md` 文件的目录（`README.md` 为索引，不作为条目解析）。单条条目格式如下：

```markdown
## 条目名
- id: <32 位十六进制>
- 触发词: 钟楼, 报时, 停摆
- 常驻: 否
- 优先级: 5
- 内在价值: 50
- 连带触发词: 无

正文……
---
```

字段说明：

- **触发词**：命中后激活条目，支持中英文逗号、顿号分隔；
- **常驻**：设为「是」时始终注入；
- **优先级**：1–10，用于激活后的排序参考；
- **内在价值**：0–100，抗遗忘基准；
- **连带触发词**：本条命中时顺带激活其他条目（最多一层）。

通过 **设置 → 系统提示词** 内的世界书编辑器，可以打开已有角色/故事世界书、选择任意目录或 `.md` 文件、新建世界书，并进行关键词搜索与条目增删改。保存时会自动补全缺失的 `id`、生成 `.bak` 备份并原子替换；同文件内触发词重复仅提示，不阻止保存。

## 6. 故事区

### 6.1 新建故事

在主页面首页将模式滑块切换到 **故事**，点击 **「+ 新建故事」** 打开表单，可填写：

- **标题**（必填）；
- **角色**（从提示词库选择）；
- **剧本世界书目录**（可空）；
- **世界书档位**：**两段都注入**（角色世界书 + 剧本世界书）或 **完全覆盖**（仅注入剧本世界书，选择此项时必须填写剧本世界书目录）；
- **背景与剧本设定**（可空，作为设定层注入，不是首条消息）；
- **你的设定（画像）**（可空，写入该故事的 `profile.md`，每轮注入，留空不注入）；
- **开场消息**（可空，非空时作为根分支的第一条 assistant 消息）。

创建完成后自动进入该故事的活跃分支。也可以通过对话导入功能直接从酒馆 JSONL 或 NC 备份创建新故事区（见 10.2）。

### 6.2 分支与检索

故事页右侧的 **分支** 抽屉包含四部分：

- **导入为新分支**：直接从酒馆 JSONL 或 NC 备份文件导入单会话作为当前故事区的新分支（角色锁定跟随当前故事，可选是否导入后设为活跃分支）；
- **检索**：在当前故事的**全部分支**内搜索，显示所属分支、消息序号、角色（我 / 她 / 旁白）与命中片段；点击结果会自动切换到对应分支，并滚动短暂高亮该消息；
- **分支列表**：扁平展示每条分支的消息数、最近活动时间与派生来源快照（「从「某分支」第 N 条之后分出」）；点击即可切换；
- **消息时间轴**：定高窗口，默认贴底停在最新一条，向上滚动查看历史；每条消息旁提供「由此分支」按钮。

分支行为规则：

- 派生新分支会复制分叉点之前的消息前缀（含旁白）并立即激活新分支；
- **分支之间互相独立**：后续修改或删除源分支，不影响已派生分支的消息、检索与记忆召回；
- 可删除任意分支（包括当前分支，删后自动切换到最近活动的分支），唯独**最后一条分支不可删除**；删除分支不可恢复。

### 6.3 旁白

故事页输入框左侧提供 **对话 / 旁白** 切换按钮（普通 Chat / Agent 不显示）：

- 切到 **旁白** 发送的内容**不调用模型**，不产生用户气泡，而是以居中文字「旁白：……」写入并持久化；
- 下一次触发回复时，旁白会作为独立的 `system` 消息（带「系统旁白：」前缀）进入模型上下文；
- 生成期间不可插入旁白。

### 6.4 故事设置、删除与数据路径

在 **设置 → 故事区** 可以修改故事的标题、概要、角色、背景设定、世界书目录与档位，编辑用户画像，查看/删除/清空该故事的长期记忆，或删除整个故事区。

删除故事区会连同其分支与记忆库一并删除（不可恢复），删除前自动备份到 `userData/stories/.trash/`。

每个故事区的数据目录结构为：

```text
userData/stories/<storyId>/
├─ story.json        元信息
├─ branches.json     分支列表与可见性快照
├─ profile.md        用户画像（可不存在）
└─ memory.db         该故事独立的长期记忆与轮次归档库
```

## 7. 工作区与工具权限

### 7.1 工作区

工作区是本地目录边界，决定 Agent（及开启工具增强的 Chat）可访问的文件根目录：

- 左侧栏在 Agent 模式下显示工作区列表，支持多工作区管理与切换；
- 对话页底部也可切换当前会话的工作区；
- 删除工作区后，依赖它的会话会重新指派到其他活动工作区；
- 零工作区时 Agent 输入区进入门禁引导态，点击即可新建工作区。

### 7.2 权限模式与内置工具

在 **设置 → 工具权限** 可切换三种全局权限模式（下一次工具调用立即生效）：

| 模式 | 只读工具 | 有副作用工具 | 路径范围 |
| --- | --- | --- | --- |
| 只读 | 直接执行 | 一律拒绝 | 限工作区内 |
| 审批（默认） | 直接执行 | 弹出确认卡，超时按拒绝处理 | 限工作区内 |
| 完全访问 | 直接执行 | 直接执行 | 不受工作区限制 |

当前内置工具均为只读工具：

- `fs.list_dir`：列出工作区目录，最多返回 200 项；
- `fs.read_file`：读取工作区文本文件，最多返回 64 KB，自动拒绝疑似二进制文件；
- `clock.now`：获取本机或指定 IANA 时区的当前时间（每轮对话也会自动注入本机时间块）。

工具执行出错时会作为工具结果回喂给模型，不会中断整轮对话。

### 7.3 Chat 工具增强

Chat 默认不供给工具。若需在 Chat 中使用工具：

1. 在 **设置 → 工具权限 → Chat 工具增强** 开启总开关；
2. 逐个勾选允许供给的工具；
3. 保存设置。

总开关关闭时 Chat 拿不到任何工具，但已勾选列表会保留。这里控制「是否供给」，最终能否执行仍受权限模式与渠道授权约束。

## 8. 长期记忆、摘要与故事召回

**设置 → 长期记忆** 页面自上而下分为四块：**对话摘要** → **故事区 RAG 召回** → **事实记忆（普通聊天使用，折叠面板）** → **危险区**。

单轮请求的上下文注入顺序为：

```text
系统提示词 → 当前时间 → RAG 事实记忆 → 故事区对话召回（仅故事模式）→ 对话摘要 → 近期历史消息
```

### 8.1 对话摘要（滚动压缩）

用于解决长对话超出上下文窗口的问题（存储于 `userData/summaries.json`）：

- 每累积达到 **触发条数**（默认 40 条未压缩消息），后台并发压缩为四段：**近期话题 / 你的信息 / 重要约定 / 长期经历**；
- 之后每轮请求注入这四段摘要，历史原文仅保留最近 **保留窗口** 条（默认 12 条）；
- 压缩在后台异步运行，不阻塞当前回复；任一段失败则不推进游标，60 秒内不重试；
- 编辑重发、删除消息或切换分支导致游标锚点失效时，该会话摘要自动作废并回落全量历史；
- 演示模式下不触发压缩；工具输出不进入摘要；
- 支持在设置页即时调整开关、触发条数、保留窗口、四段字符上限，或执行「忘掉当前会话的摘要」「清空全部摘要」（均不影响原始聊天记录）。

### 8.2 故事区 RAG 召回（历史原文按轮召回）

除事实记忆外，故事区还会将已闭合的剧情对话按轮归档（以 `assistant` 回复闭合；用户手动中止的轮次会被排除），在后续对话中按需召回窗口之外的早期剧情原文：

- **后台归档**：每轮结束后异步切分（单块 1,200 字符、重叠 160 字符）并写入该故事的 `memory.db`，失败不影响对话；
- **按轮检索**：`最多召回轮数 N` 按「轮」计数（默认 4 轮，范围 1–20），同一轮命中多个切片只占一个名额；已在近期上下文窗口中的轮次不会重复注入；
- **可调参数**（**设置 → 长期记忆 → 故事区 RAG 召回**）：总开关、最多召回轮数 `N`、token 预算（默认 8,000，范围 1,000–32,000）、相似度阈值（默认 0.4）、关键词权重（默认 0.5）、补查较新状态深度（默认 32，0 表示关闭），以及只读状态（已归档轮数、已有向量轮数、向量可用性、最近一次召回情况）；
- **校验约束**：**关键词权重必须严格大于相似度阈值**，否则界面禁止保存，以确保无向量时纯关键词路径仍可命中；
- **当前限制**：目前归档切片的 `embedding` 字段写入为 `NULL`，因此故事区召回在生产中实际走**纯关键词路径**，状态面板会明确标注向量不可用。

### 8.3 事实记忆（普通聊天 RAG）与一键下载模型

折叠面板 **事实记忆（普通聊天使用）** 负责跨会话提取并检索用户说过的稳定事实（存储于 `userData/memory.db`）：

- 采用「本地向量相似度 + SQLite FTS5 关键词」混合检索，对话内容不发往外部做 embedding；
- 支持开关总开关、自动提炼开关，调整 `topK`（默认 5）、token 预算（默认 1,200）、分数下限（默认 0.55），并提供「试召回」调试框查看综合分、向量分与关键词分；
- **按人查看与清理**：按用户汇总展示人设数、RAG 事实条数与人设历史条数；点「查看」可展开各人设详情、手动添加或删除单条记忆、删除非激活人设、查看主库路径与租户 `(user_id, persona_id)`，以及执行 **按人删除**（仅删除该人的记忆、历史、人设、摘要与私聊记录，保留其渠道授权，不影响群聊与故事区）。

**一键下载 embedding 模型**：

本地向量模型 `Xenova/bge-m3`（约 587 MB）不随安装包分发，可在 **事实记忆 → 运行状态** 点击 **「一键下载并配置模型」**：

| 项 | 说明 |
| --- | --- |
| 存放目录 | `<userData>/models/Xenova/bge-m3/`（升级重装不丢失） |
| 下载文件 | `config.json`、`tokenizer.json`、`tokenizer_config.json`、`onnx/model_quantized.onnx`（q8） |
| 镜像回退 | 优先 `hf-mirror.com`，失败自动回退 `huggingface.co` |
| 原子校验 | 先写 `.part` 临时文件并校验真实体积，下载完成后自动清除加载失败缓存，下次检索即时生效 |

未安装模型时不会阻断对话，事实记忆自动降级为纯关键词检索。设计细节见 [docs/04-RAG记忆检索设计.md](https://www.google.com/search?q=docs/04-RAG%E8%AE%B0%E5%BF%86%E6%A3%80%E7%B4%A2%E8%AE%BE%E8%AE%A1.md)。

### 8.4 记忆分区规则

| 维度 | 分区规则 |
| --- | --- |
| 用户隔离 | 按 `user_id` 隔离（桌面端为 `root`，QQ 端为发言者 QQ 号），不同用户的记忆互不可见 |
| 人设隔离 | 按 `persona_id` 隔离；同一用户切换人设即切换对应记忆与人设历史 |
| 场景共享 | 桌面、QQ 私聊、QQ 群聊**不再二次切分**，同一 `(user_id, persona_id)` 跨场景共享 |
| 故事隔离 | 每个故事区拥有物理独立的 `stories/<storyId>/memory.db`；派生分支时会固化可见性快照，避免不同分支记忆串味 |
| 群旁听语料 | `observe/` 为只增不清的原始语料，不进入记忆库，也不参与提示词注入 |

### 8.5 清空全部数据（危险区，不可撤销）

位于 **设置 → 长期记忆 → 危险区 → 「清空全部数据（不可撤销）」**，在列表态即可直接访问：

1. 点击按钮后弹框列出完整的「将删除」与「将保留」清单；
2. 点击 **「我明白，生成验证码」**，主进程生成 8 位十六进制验证码（5 分钟有效、不可选中；输错 1–2 次清空重填且码不变，输错 3 次关闭弹框并提示失败）；
3. 校验通过后，主进程先对关键数据做一致性备份（SQLite 使用 `VACUUM INTO` 快照，跳过 `-wal`/`-shm` 侧车）并逐项校验——**备份失败则中止，不删任何文件**；
4. 清空完成后自动重启应用。

- **删除范围**：`sessions.json`（重置为 `[]`）、`memory.db` 三张表（记忆 / 人设历史 / 用户人设）、`stories/` 整目录、`summaries.json` 摘要条目，以及遗留的 `zones.json.retired-bak`；
- **保留范围**：`settings.json`、`channels/`（授权名单）、`observe/`、`snowluma/`、`presets/`、`workspace/`、`qq/settings.json`、`models/`、`Local Storage` 与 `Cookies` 等；
- **备份位置**：与 `userData` 同级的备份目录（例如 `%APPDATA%\Nahida Chat.p7-backup-<时间戳>`）。由于与原数据在同一块磁盘且不会自动清理，如需防磁盘故障请自行异地备份。

## 9. 渠道控制台与 QQ 接入

### 9.1 渠道控制台

**设置 → 渠道控制台**以 `userData/channels/access.json` 为授权真源，按「人」与「群」控制权限：

- **机器人 QQ 号**：自动从已注入的 QQ 进程读取（或手动填写兜底），仅用于展开群会话键，不参与授权判定；
- **QQ 号白名单**：每行一个账号，分别配置 **私聊**、**群聊**、**工具** 三个布尔权限位，以及正交的 **指令等级**（无 / 低 / 中 / 高）；
- **群白名单**：控制允许响应的群号（未入白名单的群不会回复，但消息仍会进入旁听库）；
- **鉴权开关**：
  - **群成员鉴权**（默认关）：开启后，群内仅勾选「群聊」位的账号 @ 她才会回复；
  - **工具调用拦截**（默认开）：仅勾选「工具」位的账号可真正执行工具；
  - **群聊工具增强**（默认开）：控制群聊在开启「Chat 工具增强」时是否供给工具（群里可用工具需同时满足供给开关开启、账号勾选「工具」位、且符合全局工具权限模式）；
- **渠道工作区**：QQ 会话读写文件的统一根目录，默认为 `<userData>/workspace`；
- **渠道模型**：只读展示当前生效的默认档案与默认模型；
- **旁听库**：展示群聊/私聊采集概要，点击 **「群号一览（可搜索）」** 可按群号、群名或账号组合搜索并查看近期语料（只读，不提供清空入口）。

### 9.2 QQ 接入步骤

1. 先启动并登录本机 QQ；
2. 打开 **设置 → QQ 接入**，点击 **刷新** 查看检测到的 QQ 主进程；
3. 在目标 PID 行点击 **注入**（程序不会自动挑选进程）；
4. 状态变为「在线 / 已注入」后，前往 **设置 → 渠道控制台** 配置账号与群白名单；
5. 通过 **最近事件** 面板排查每条消息的回复、指令执行或丢弃原因。

如宿主状态提示降级，请确认 `out/snowluma-host`（打包版为 `resources/snowluma-host`）下的 `node.exe` 与 `index.mjs` 完整存在，再点击 **重启宿主**。

### 9.3 QQ 行为开关与渠道指令

在 **设置 → QQ 接入 → 行为开关** 中可调整私聊 typing 提示、群聊是否必须 @、群聊首段是否 @ 提问者、段间延迟、单句段数上限、单段码点上限、每用户/每渠道 60 秒限速以及出错兜底回复（需点击 **保存设置** 生效）。

在 **设置 → QQ 接入 → 指令门槛** 中，可为四条渠道专用人设指令设置所需最低等级（`无 < 低 < 中 < 高`），**下拉选择后立即保存生效**，无需点击上方的保存按钮：

| 指令 | 作用 |
| --- | --- |
| `//list` | 列出当前账号的全部人设（标出激活项） |
| `//switch <人设名>` | 切换当前激活人设（下一句起写入该人设记忆域） |
| `//add <人设名>` | 新建人设（不改变当前激活项） |
| `//dele <人设名>` | 删除指定非激活人设及其记忆与历史（`default` 不可删） |

渠道指令仅在 QQ 渠道生效，以 `//` 开头且不会发送给模型。

## 10. 数据、对话迁移与隐私

### 10.1 主要数据路径

可在 **设置 → 关于 → 数据目录** 查看本机 `userData` 路径：

| 路径 | 说明 |
| --- | --- |
| `settings.json` | 模型档案、工具权限、记忆与故事召回参数、对话摘要参数、工作区、外观、桥接开关 |
| `sessions.json` | 普通会话、故事分支会话、旁白、思考过程与消息历史 |
| `memory.db` | 主长期记忆库（RAG 事实记忆、用户人设与人设聊天历史） |
| `summaries.json` | 对话滚动摘要 |
| `stories/<storyId>/` | 故事元信息、分支、用户画像与独立记忆/归档库 |
| `stories/.trash/` | 删除故事区前的自动备份 |
| `channels/access.json` | 渠道按人授权与群白名单 |
| `observe/` | 只增不清的群/私聊旁听语料 |
| `nc-bridge/` | ST 桥接运行配置（`config.json`）、最高权重规则（`st-override.md`）与孤儿清理账本（`orphans.json`） |
| `prompt/` | 用户自定义角色与 `shared/` 覆盖文件 |
| `workspace/` | 默认工作区 / 默认渠道工作区 |
| `snowluma/` | QQ 宿主运行时数据 |
| `models/` | 本地 embedding 模型目录 |

### 10.2 对话迁移（导入与导出）

Nahida Chat 支持在 **SillyTavern（JSONL）** 与 **Nahida Chat 备份（`.nc.json`）** 之间导入和导出桌面会话，不涉及 QQ 渠道会话。

**操作入口**：

- **设置 → 数据与备份**：集中提供「对话导入」与「对话导出」（可选单个桌面会话或全部桌面会话）；
- **左侧栏底部「导入对话」**：随时导入为新故事区或 Chat / Agent 会话；
- **故事分支抽屉「导入为新分支」**：将单个会话导入为当前故事区的新分支；
- **对话页右上角「⋯」按钮**：直接导出当前会话或全部桌面会话。

**导入行为**：

- **自动识别与先预览再落库**：支持 `.jsonl` 与 `.json`（`.nc.json`），单文件上限 **64 MiB**、最多 **20,000 条消息**。选择文件后先展示预览（格式、会话数、消息数、各角色计数、跳过坏行数、丢弃扩展字段数、首尾摘要、角色匹配与重复导入次数），点击「确认预览并导入」后才会创建会话；预览有效期 10 分钟，期间若源文件被修改会自动失效。
- **目标与角色匹配**：可导入为「新故事区」「已有故事区的新分支」（故事区每次限导入 1 个会话）或「Chat / Agent 会话」。若酒馆聊天头行中的角色名为 `unused`、`unknown`、`character` 等占位符，标题与角色匹配会自动回落到**文件名并去掉日期后缀**。
- **保留字段与防覆盖**：NC 备份导入时会保留工具调用、思考过程、错误与告警信息（原未完成的 `streaming` 消息会收敛为错误态）；重复导入同一文件时只提示历史导入次数，始终创建独立副本，不覆盖既有会话。

**导出行为**：

- **NC 备份（`.nc.json`）**：单文件打包单个或全部桌面会话的完整消息记录；
- **酒馆 JSONL（`.jsonl`）**：逐会话导出为独立文件；若包含故事旁白，导出完成后会提示「N 条旁白在酒馆侧会变成角色发言」；
- **不静默覆盖**：目标目录存在同名文件时自动编号保存。

### 10.3 建议完整备份集合

若需连同模型配置、记忆库、世界书与授权一并备份，请先退出应用，确保 SQLite 的 `-wal` / `-shm` 日志已正确回收。最小备份集合为：

- `settings.json`
- `sessions.json`
- `memory.db`
- `summaries.json`
- `stories/`
- `channels/access.json`
- `prompt/`
- `nc-bridge/`（如使用 ST 桥接）

### 10.4 隐私与安全边界

- 所有会话、故事、记忆、世界书与提示词均保存在本机；
- `apiKey` 当前明文存于 `settings.json`，切勿公开上传；
- 使用远程模型时，提示词、上下文、工具结果、记忆与故事召回命中片段会随请求发送给模型服务商；如需完全离线，请使用本地 Ollama；
- 工具的「完全访问」模式不受工作区目录限制，请仅在完全信任当前任务时开启；
- QQ 渠道没有交互式审批卡片，因此全局处于「审批」模式时，有副作用的工具在 QQ 中等同于拒绝。

## 11. 开发、测试与发布

### 11.1 常用开发命令

```bash
pnpm typecheck                  # 主进程 + 渲染进程 TypeScript 类型检查
pnpm test                       # 完整行为测试链（76 项）
pnpm build                      # electron-vite 构建 + Snowluma 宿主构建（含 SHA-256 清单）
pnpm ui:map --only=<视图名>      # 仅重拍改动视图并合并更新 docs/ui/UI_MAP.md
pnpm ui:map --all               # 公共样式或全局布局改动时全量重拍
```

### 11.2 打包与发布

```bash
pnpm package:dir                # 生成免安装目录 release/win-unpacked
pnpm package:win                # 生成 Windows NSIS 安装包 release/Nahida-Chat-Setup-<版本>-x64.exe
pnpm release:check              # 单独校验宿主资源完整性
pnpm release:verify             # 使用打包产物中的宿主执行握手自检
```

打包说明：

- NSIS 安装包自带 Electron 运行时与 Snowluma 宿主（含 `node.exe` 与原生模块），终端用户无需安装 Node.js 或 pnpm；
- 宿主与内置提示词作为独立资源（`resources/snowluma-host`、`resources/prompt`）分发，不打包进 `app.asar`；
- `beforePack` 与 `afterPack` 两道门禁会按全量 SHA-256 清单校验宿主资源，缺文件或哈希不符即中止打包；
- 安装包升级仅覆盖程序目录，不改动 `%APPDATA%\Nahida Chat` 下的用户数据与已下载的 embedding 模型。

### 11.3 开发模式清空数据后的重启行为

在 `pnpm dev` 环境下执行「清空全部数据」后，应用会拉起新的开发链路（Vite dev server + Electron），因此原终端命令退回提示符、几秒后自动弹出新窗口属于正常现象；期间请勿手动重复执行 `pnpm dev`，以免触发单实例锁冲突。打包版则直接调用 Electron 原生 `app.relaunch()`。

## 12. 已知边界与当前限制

- **无自动更新**：目前支持生成安装包，但客户端不会自动检测或下载新版本；
- **密钥未加密**：`apiKey` 明文写入 `settings.json`，尚未接入 `safeStorage`；
- **故事区召回当前仅走关键词路径**：归档轮次切片的 `embedding` 字段暂为 `NULL`，设置面板会提示向量不可用；
- **ST 桥接前置条件与形态**：需自备 ST 目录、手动导入角色卡并在 ST 中配置模型；仅作用于非渠道的 `story` 会话；每轮收尾含约 10.5 秒观察窗口且正文非流式展示；单轮上限以外的就绪/连接超时为固定值；上下文预算分层默认保留 35% 给 ST 侧，必要时需在 `nc-bridge/config.json` 中手动调整或关闭；
- **ST 预设 HTML 宿主脚本**：包含 `<iframe>`、`<script>`、`<style>` 的替换脚本会被安全拦截并降级为纯文本折叠卡，不渲染原 HTML 宿主；
- **对话迁移边界**：单次导入上限为 64 MiB / 20,000 条消息；导出仅覆盖桌面会话（不含 QQ 渠道会话）；导出为酒馆 JSONL 时，故事旁白会转换为角色发言并给出提示；
- **内置工具均为只读**：当前仅提供 `fs.list_dir`、`fs.read_file` 与 `clock.now`，不包含通用写文件或命令执行工具；
- **思考过程随会话落盘**：推理模型的长思考文本会写入 `sessions.json`，当前暂无「不保存思考」选项；
- **单分支删除无备份**：仅删除整个故事区时会备份至 `stories/.trash/`，删除单条分支不可恢复；
- **QQ 注入环境依赖**：依赖本机 Windows 与 QQ 客户端环境，不保证适配所有 QQ 版本；
- **外观与窗口**：仅支持单窗口及浅色 / 深色 / 跟随系统三种主题模式。
