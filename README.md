# Nahida Chat

本地优先的桌面端 AI 聊天客户端。Electron + Vite + React + TypeScript，主进程持有全部真实能力，渲染进程只做展示。

当前状态：`M0 可运行骨架` + 设置页重构——窗口能起、消息能流式回来、设置能落盘、模型档案可管理、
提示词按角色分目录直接改文件、新建对话时可选 Chat / Agent 模式。

## 快速开始

```bash
pnpm install        # 依赖（npmmirror 源，含 electron 二进制兜底）
pnpm dev            # 开发模式，改动即时热更新
pnpm typecheck      # 主进程 + 渲染进程分别做一次类型检查
pnpm test           # 模型档案落盘 + 提示词库拼装的行为测试
pnpm build          # 产物输出到 out/
pnpm ui:map         # 重新生成 docs/ui/ 下的可定位截图与坐标
```

> 首次启动默认是「演示模式」：完全离线，回复由本地回显生成，**不会**调用任何远程模型。
> 接真实模型：左下角「设置 → 模型配置」新建档案，选预设（OpenAI / DeepSeek / Anthropic…）或自定义，
> 填 apiKey 后点「获取可用模型」勾选清单（或直接手动填模型 ID），
> 再点「测试连接」确认通了，最后「保存档案」并「设为默认」。

## 对话区的两个选择器

输入框下方有两个下拉：**模型** 和 **权限**。

- **模型**：按档案分组列出所有可选模型，切换写进当前会话；新会话沿用默认档案。
  长对话中途换模型不会影响已经跑完的那一步，下一次请求才生效。
- **权限**：只读 / 审批 / 完全访问（见下节）。和设置页「工具权限」是同一份配置，
  两处改都一样。切到完全访问时选择器会变成警示色。

## 工具权限

设置页「能力与安全 → 工具权限」只有两项：工作区目录 + 权限模式。

| 模式 | 只读工具 | 有副作用的工具 | 文件路径 |
| --- | --- | --- | --- |
| 只读 | 直接执行 | 一律拒绝 | 限工作区内 |
| 审批（默认） | 直接执行 | 弹卡确认 | 限工作区内 |
| 完全访问 | 直接执行 | 直接执行 | 不限 |

工具只声明「会不会改东西」这一个属性，不再有风险分级——用户能判断的是行为，不是分类学。
旧配置里的 `toolPolicy` / `workspaceRoots` 会在启动时自动迁移成新形态。

## 长期记忆（RAG）

设置页「能力与安全 → 长期记忆」可以开关、调参、查看/编辑/删除每一条记忆，
还能用一段话试召回、看到每条命中的分数。

- 全链路本地：embedding 用本地 ONNX 模型，对话内容不外发。
- 混合检索：向量（语义）+ SQLite FTS5（关键词）融合。
- 每轮只在开头检索一次，注入预算由用户自己定（不设硬上限），超预算整条丢弃、不切半句。

**首次使用需要手动放模型**（不进仓库，约 543 MB）：

```
models/Xenova/bge-m3/     ← 见 docs/04 第 12 节的完整文件清单与下载地址
```

模型缺失不会报错：记忆自动降级为纯关键词检索，其余功能不受影响。

## 已知边界

- apiKey 目前明文存在 `userData/settings.json`，M2 才会用 `safeStorage` 加密。
- 没有打包配置（electron-builder 排在 M5）。
- 只有一个窗口、一种主题、无快捷键。
