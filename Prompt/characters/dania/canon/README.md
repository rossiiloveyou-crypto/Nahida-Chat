# 原作台词基准 · 使用说明

> 这个目录放「她说话长什么样」的台词样本。本文件（README.md）不参与拼装。

## 文件分工

| 文件 | 是否注入 | 作用 |
| --- | --- | --- |
| `quotes.md` | **是** | 真正生效的台词样本。可以拆成多个文件（`quotes-日常.md`、`quotes-情绪.md`），按文件名排序拼接 |
| `_template.md` | 否（`_` 前缀跳过） | 填写模板，照着它补台词 |
| `README.md` | 否 | 本说明 |

## 现状

- `quotes.md`：13 个既定场景 + 3 个扩展场景（4.1 比喻 / 4.2 孩童心性 / 4.3 洞察与祝福），共 81 条台词。
- 允许自由增补 `### 4.4 …` 这样的新场景，程序按文件名与行序原样拼进去，不需要改代码。

## 四条容易踩的坑

1. **文件名用小写**。文档里写的是 `quotes.md`；写成 `Quotes.md` 在 Windows 上能读到，但和其它平台/脚本对不上，排查时很费劲。
2. **不要留第二份副本**。复制出 `Template.md`、`quotes copy.md` 这类文件会被当成正式台词再注入一遍，同一批台词进两次。文件名以 `_` 开头或叫 `template.md` 的会被跳过，其余一律读取。
3. **不要从网页直接粘**。粘贴会把 `<` `>` `"` 转成 `&lt;` `&gt;` `&quot;`，注释一旦被转义就剥不掉，整段填写说明会进提示词。程序会先解这五个实体再剥注释，但保持源文件干净更稳妥。
4. **注释里不要再写注释符号**。`<!-- … <!-- … --> … -->` 会在第一个 `-->` 处提前闭合，后面的说明就变成正文了。

## 三条写作规矩

1. **只收原作原句**：游戏剧情、角色语音、角色演示、传说任务、尘歌壶交互、角色名片。自己编的句子会把角色写偏，比不写更糟。
2. **一条只示范一件事**：招呼、留钩子、把沉重说轻、打比方、克制划界……一条台词同时教三件事，模型会学杂。
3. **覆盖优先于条数**：宁可每个场景 2 条，也不要把 20 条堆在「开心」上——空场景模型不会自己补。

## 和相邻文件的分界

| 想问的事 | 看哪个文件 |
| --- | --- |
| 她是谁、怎么想事 | `../soul.md` |
| 她怎么说话（句式、语气词、比喻用量） | `Prompt/shared/tone.md` |
| 她说过的原句长什么样 | 本目录 `quotes.md` |
| 这个模式下的职责与边界 | `../modes/*.md` |
| 这个模式下具体的表达节奏 | `../styles/*.md` |

> 台词样本不承担「规则」职责：不要在这里写「她不许说某某词」，那是 `shared/tone.md` 的事。
