## 2. 需求审计

### 2.1 配色：草图里有一处自相矛盾（必须现在定，否则会污染整套令牌）

草图给了四种描述：

| 写法 | 换算 | 结果 |
| --- | --- | --- |
| `#FFFDFDE3` | 8 位色 = RGB(255,253,253) + alpha 0xE3 | 近白偏粉，**不是**奶油色 |
| `rgb(253,253,227)` | → | `#FDFDE3` 奶油黄 |
| `cmyk(0,0,10,0)` | Y=10% → RGB(255,255,229) | `#FFFFE5`（与上者差 2/2/2，属取整） |
| `hsv(60.0, 10.28%, 99.22%)` | V=253, S=10.28% → RGB(253,253,227) | `#FDFDE3` 完全吻合 |

**结论：四种描述里三种指向 `#FDFDE3`，只有 `#FFFDFDE3` 例外。**
判断 `#FFFDFDE3` 是多打了一个 `FF` 前缀的笔误（`#FDFDE3` 前面误加了 `FF`），不是刻意要 89% 透明度。

- **落地取值：`#FDFDE3`**（不透明），已写进 `src/renderer/src/styles/tokens.css` 与 `src/shared/constants.ts`。
- 如果确实需要"奶油色半透明覆盖层"，用 `rgba(253, 253, 227, 0.89)` 单独做一层，**不要**把它当根背景——根背景一旦透明，会和系统主题、窗口阴影混色，跨机器观感不一致。

### 2.2 界面结构

草图的约束只有三条，已全部满足：

1. 奶油底 + 白色聊天窗口 + 白色输入框 —— 已实现（聊天面板纯白卡片，输入区白底描边）。
2. 左下角设置入口 —— 已实现（侧边栏固定底部，激活态高亮）。
3. 设置页先有页面 —— 已实现，并**顺手做成了可用**：模型接入、系统提示词选择、关于信息都能真实读写。

> 之所以没做成纯占位页：设置里的"模型来源"是对话能否跑通的前置条件，做成假表单只会让下一轮再返工一次。

### 2.3 目录结构

你的要求是 `<功能文件夹>\<功能1>\代码` + 独立的 `Prompt\` 目录。已按"功能优先"落地：

```
src/main/features/<功能>/     ← 主进程能力（chat / llm / prompt / settings）
src/renderer/src/features/<功能>/  ← 对应界面（chat / settings）
Prompt/                        ← 全部提示词，一个文件一个意图
```

没有采用 `components/` 一把梭 + `pages/` 的经典分层，因为这套软件的复杂度集中在**功能纵向切面**（对话、模型、提示词），横切分层会让一个功能的代码散在四个目录里。

### 2.4 功能边界（借鉴 Cyrene 的部分 vs 我们自己要写的）

按你的定位——"借鉴功能，不基于它改造"——建议划成两条线：

**要借鉴的（做同类能力，不抄代码）**

- 多会话管理 + 会话持久化
- 流式输出与中断
- 模型/服务商配置（多 provider）
- 提示词与角色（Prompt 目录化）
- 工具/技能调用（M3 之后再谈）

**必须我们自己定的（Cyrene 不会替我们回答）**

- 数据放哪：纯本地 vs 可同步
- 密钥怎么存：明文 JSON vs `safeStorage` vs 系统钥匙串
- 单窗口 vs 多窗口/托盘常驻
- 是否要"本地模型"（Ollama/llama.cpp）支持

## 3. 技术选型审计

| 方案 | 优势 | 代价 | 结论 |
| --- | --- | --- | --- |
| **Electron + Vite + React + TS** | 生态最全；文件/网络/系统能力开箱即用；与你现有 DSH Desktop 同栈，排障经验可复用；Cyrene 同栈，借鉴时心智模型一致 | 安装包 ~100MB+；内存占用高于原生 | ✅ **采用** |
| Tauri | 体积小、内存低 | 需要 Rust 工具链（本机没有）；WebView2 版本碎片化，富文本/流式渲染踩坑多 | ❌ 本轮排除 |
| 纯 Web（Vite + React） | 最轻 | 拿不到本地文件与系统能力，`Prompt/` 目录、本地会话库都做不了 | ❌ 与"桌面软件"定位冲突 |

选 Electron 的**决定性理由**不是性能，而是：这个产品 80% 的复杂度在"模型接入 + 提示词 + 本地数据"，不在渲染性能。Electron 把这些全部变成普通 Node 代码。

## 5. 需要你拍板的 5 个问题

1. **数据要不要出本机？** 纯本地（默认）/ 可选云同步 / 必须云同步——这决定 M1 是只写 SQLite 还是要设计同步协议。
2. **接哪些模型？** 只做 OpenAI 兼容（当前实现）/ 还要 Anthropic、Gemini、Ollama 原生协议 / 要"多模型对比"？
3. **对话的组织方式？** 线性单线程（当前）/ 需要消息分支（编辑历史消息生成分叉）/ 需要"项目/知识库"维度？
4. **要不要工具能力？** 只聊天 / 要读本地文件 / 要联网搜索 / 要执行命令——这一项直接决定安全模型，越早定越好。
5. **分发方式？** 只自己用（免签名）/ 团队内分发 / 公开发布（要签名、要更新器、要崩溃上报）。

前 3 个问题不定，M1 会返工；后 2 个可以在 M2 之后补。
