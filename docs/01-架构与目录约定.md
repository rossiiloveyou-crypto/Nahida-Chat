# 01 · 架构与目录约定

## 1. 分层

```
┌──────────────────────────────────────────────┐
│ renderer（React）                             │ 只看数据、只发意图
│   拿不到 Node / fs / net / ipcRenderer         │
└───────────────────┬──────────────────────────┘
                    │ window.nahida（contextBridge）
┌───────────────────▼──────────────────────────┐
│ preload                                        │ 只做转发，不写业务
└───────────────────┬──────────────────────────┘
                    │ ipcMain.handle / webContents.send
┌───────────────────▼──────────────────────────┐
│ main（Node）                                   │ 唯一真实能力持有者
│   features/chat  llm  prompt  settings         │ 会话、模型、提示词、配置
└──────────────────────────────────────────────┘
```

一句话规矩：**渲染进程永远不知道数据从哪来，主进程永远不关心怎么显示。**

## 3. 四条硬规矩

1. **能力只从 main 出。** 渲染进程要读文件、发网络、存数据，一律"加一个 IPC handler"，不要在 preload 里塞业务逻辑。
2. **契约先写 `shared/`。** 任何跨进程的数据结构，先在 `shared/types.ts` 定义，再写实现。禁止在两端各写一份"差不多的接口"。
3. **色值只在 `tokens.css` 出现一次。** 组件里用 `var(--nc-*)`，不要写 `#FDFDE3` 字面量。
4. **功能按纵向切。** 新增一个能力 = `main/features/<名字>/` + `renderer/src/features/<名字>/`，不要新建一个横跨一切的大文件。

## 5. 数据落盘

| 内容 | 位置 | 格式 |
| --- | --- | --- |
| 应用配置（含模型档案） | `userData/settings.json` | JSON，临时文件 + rename 原子写 |
| 提示词 | 项目 `Prompt/`（打包后 `resources/prompt`） | Markdown，用户直接编辑 |
| 会话历史 | `userData/sessions.json` | JSON 数组，同上 |
| 长期记忆 | `userData/memory.db` | SQLite（`node:sqlite` + FTS5），见 [04](04-RAG记忆检索设计.md) |
| embedding 模型 | 项目 `models/`（打包后 `resources/models`） | ONNX，不进仓库 |

> `userData` 在 Windows 上是 `%APPDATA%\Nahida Chat`。设置页"关于"里能看到真实路径。
> M1 会把 `sessions.json` 换成 SQLite——消息一多，整文件重写的代价会变得不可接受。

### 提示词拼装（`main/features/prompt/promptStore.ts`）

每次请求现场读文件，按下表顺序拼成一条 system 提示词。顺序即权重，越靠后越贴近这次回答。

| # | 环节 | 文件 | 生效模式 |
| --- | --- | --- | --- |
| 1 | 全局底线 | `shared/base.md` | 两种 |
| 2 | 语气与句式 | `shared/tone.md` | 两种 |
| 3 | 人格核心 | `characters/<角色>/soul.md` | 两种 |
| 4 | 背景设定 | `characters/<角色>/worldbook/*.md` | 两种 |
| 5 | 模式规则 | `characters/<角色>/modes/<mode>.md` | 按模式二选一 |
| 6 | 表达风格 | `characters/<角色>/styles/<mode>.md` | 按模式二选一 |
| 7 | 工具规范 | `shared/tool_usage.md` | 仅 Agent |

缺哪段跳过哪段，不抛错。角色目录整个缺失时第 1、2、7 段仍然注入——缺人格不等于失去执行纪律。
记忆走独立的第二条 system 消息，不拼进人格提示词（人格是「怎么说话」，记忆是「已经知道什么」，可撤销性不同）。

## 6. 安全边界

- `contextIsolation: true` / `nodeIntegration: false` / `sandbox: true`：渲染进程没有任何 Node 能力。
- `will-navigate` 白名单：只允许 dev server 与 `file://`，其余外链交给系统浏览器。
- `setWindowOpenHandler` 一律 `deny`，`https://` 才允许 `shell.openExternal`。
- `promptStore.openCharacter()` 做路径穿越校验：解析后必须仍在 `Prompt/characters/` 内。
- **未做**：CSP 之外的传输层加固、提示词内容审计、工具调用权限模型（M3 必须补）。

## 7. 新增一个功能的清单

```
□ shared/types.ts        定义数据结构
□ shared/ipc.ts          加频道常量
□ shared/api.ts          加 window.nahida 方法签名
□ main/features/<x>/     写实现
□ main/ipc/index.ts      注册 handler
□ preload/index.ts       暴露方法
□ renderer/features/<x>/ 写界面
□ tsconfig / 别名        一般无需改，@shared 与 @renderer 已配好
□ pnpm typecheck         0 error
□ pnpm dev               实机点一遍
```
